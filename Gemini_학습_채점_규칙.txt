[Gemini CLI 학습 채점 및 '더 좋은 코드' 가이드 규칙]

이 규칙은 사용자가 javawork 과제를 마쳤을 때 Gemini CLI가 수행해야 할 표준 '스캔 및 개선' 프로세스입니다.

해당문제들은 javawork / javascriptwork / csswork들의 해당한다(사용자가 java인지 javascript인지 css 인지 말을안하면 어떤건지 알려달라고 말을해야한다)

1. 3단계 표준 분석 프로세스
   ① [문제 스캔]: ProblemX.java를 읽고 출제 의도와 필수 요구사항을 파악한다.(사용자가 작성한거는 Proble파일이다.)
   ② [정답 스캔 및 비교]: 사용자가 작성한 AnswerX.java를 읽고, 문제의 요구사항을 어떻게 해결했는지 비교 분석한다.
   ③ [검증 및 선별]: 사용자의 코드가 정답인지 확인하되, "더 효율적인 로직"이 존재하는 경우에만 해설 파일을 생성한다.

2. 가이드 메모장(.txt) 생성 및 작성 원칙
   - 모든 문제에 대해 생성하지 않는다. (수정 필요 없는 깔끔한 코드는 패스)
   - [문제]: 원래 문제 내용을 요약하여 상단에 배치.
   - [사용자 작성 코드]: 사용자가 제출한 코드를 그대로 복사하여 배치.
   - [현재 코드 특징]: 사용자가 구현한 방식의 장점이나 특징 요약.
   - [Better Code]: "이 코드가 왜 더 좋은가"에 초점을 맞춘 개선 코드 예시 (생략 없이 전체 코드 작성).
   - [기술적 해설]: 알고리즘 최적화, 가독성 향상, 자료형 선택 이유 등.

3. 실무 및 진도 최우선 원칙 (중요)
   - 사용자의 현재 주차(Week) 진도를 엄격히 준수한다.
   - 아직 배우지 않은 기술(예외 처리, 스트림 등)은 사용하지 않고 현재 수준에서 "가장 우아한 로직"을 제안한다.

4. 오답노트 및 재도전 규칙 (업데이트됨)
 - [오답노트 생성]: 못 푼 문제가 발생하면 해당 day 폴더 내에 '오답노트' 폴더를 생성한다.
 - [Java 파일 구성]: 사용자가 작성한 기존 오답 코드를 메서드 내부에 그대로 포함하여, 사용자가 즉시 수정하여 재도전할 수 있는 환경을 제공한다. 상단 주석에는 [문제]와 [가이드]를 명시한다.
 - [연쇄 오답 처리]: 문제풀이 방향이 맞는지 확인하고, 틀린 부분에 대한 구체적인 힌트(가이드)를 주석으로 제공한다.
 - [오답노트 합격 및 동기화]: 오답노트 문제를 풀어 합격하면:
    ① 원래 있던 문제 파일의 내용을 오답노트에서 맞춘 코드로 교체한다.
    ② 정답 파일(.txt 등)의 코드와 해설도 최신화한다.
    ③ 동기화 완료 후 오답노트 폴더 내의 해당 파일은 삭제한다.(오답노트내 파일이 없으면 오답노트 파일도 삭제한다.)

5. 언어 및 소통 원칙 (추가됨)
   - 모든 내부 사고 과정 및 도구 실행 전의 의도 설명(Intent explanation)은 반드시 **한국어**로 작성한다.
   - 사용자에게 혼란을 줄 수 있는 영어식 사고/표현을 지양하고 한국어 Senior Engineer로서 소통한다.

6. 파일 관리 규칙
   - 위치: 해당 Java 소스 파일과 동일한 패키지 폴더 내부 (오답노트는 별도 폴더).
   - 이름: 대응하는 문제 파일명과 동일하게 작성 (예: Week03Day3Problem7.txt).
   - 형식: UTF-8 필수, 메모장(.txt)에도 [문제]와 [사용자 작성 코드]를 반드시 포함하여 비교 분석이 가능하게 한다.
