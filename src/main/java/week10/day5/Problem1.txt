[문제]
Serializable을 구현한 Student 클래스를 파일에 저장해보세요.
(단, 이름(String)과 나이(int) 필드를 갖는 Student 클래스를 직접 작성하세요.)

[사용자 작성 코드]
package week10.day5;

import java.io.FileOutputStream;
import java.io.IOException;
import java.io.ObjectOutputStream;
import java.io.Serializable;

public class Problem1 {
    public static void main(String[] args)
    {
        // TODO
        Student s = new Student("홍길동",20);

        try(ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("student.dat")))
        {
            oos.writeObject(s);
            System.out.println(s);
            System.out.println("객체 직렬화 완료");
        }
        catch (IOException e)
        {
            e.printStackTrace();
        }
    }

    static class Student implements Serializable
    {
        String name;
        int age;

        Student(String name, int age) {this.name = name; this.age = age;}

        @Override
        public String toString()
        {
            return String.format("Student{name = %s, age = %d}",this.name,this.age);
        }
    }
}

[현재 코드 특징]
- Serializable 인터페이스를 정상적으로 구현하여 Student 객체를 직렬화할 수 있게 설정했습니다.
- try-with-resources 문법을 적절히 활용하여 스트림 객체(ObjectOutputStream)를 안전하게 관리(자동 close)했습니다.

[Better Code]
package week10.day5;

import java.io.FileOutputStream;
import java.io.IOException;
import java.io.ObjectOutputStream;
import java.io.Serializable;

public class Problem1 {
    public static void main(String[] args) {
        Student s = new Student("홍길동", 20);

        try (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("student.dat"))) {
            oos.writeObject(s);
            System.out.println(s);
            System.out.println("객체 직렬화 완료");
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

// 1. Student 클래스를 독립적으로(또는 외부 클래스로) 선언하여 다른 클래스(Problem2)에서 캐스팅하기 쉽게 구성합니다.
class Student implements Serializable {
    // 2. 클래스의 변경 관리와 예외 방지를 위해 serialVersionUID를 선언하는 것이 실무 표준입니다.
    private static final long serialVersionUID = 1L;

    String name;
    int age;

    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public String toString() {
        return String.format("Student{name = %s, age = %d}", this.name, this.age);
    }
}

[기술적 해설]
1. serialVersionUID의 필요성
   - 자바 직렬화 과정에서 클래스의 고유 식별 번호 역할을 하는 `serialVersionUID`를 선언해 주는 것이 좋습니다.
   - 명시하지 않으면 자바 컴파일러가 클래스 구조를 기반으로 해시값을 자동 계산하여 할당하는데, 만약 필드가 추가되거나 클래스 내 사소한 부분만 수정되어도 이 값(해시값)이 변경됩니다.
   - 이로 인해 이전에 직렬화해 둔 파일을 불러올 때 인스턴스 정보가 일치하지 않아 `InvalidClassException` 에러를 발생시키므로, 버전 관리를 위해 직접 지정해 두는 것이 권장됩니다.

2. 내부 클래스(Nested class) 의존성
   - `Student` 클래스를 `Problem1` 내부의 `static class`로 두면, 실습 문제 2번(`Problem2.java`)에서 객체를 읽어 들일 때 캐스팅하기 위해 반드시 `Problem1.Student` 타입을 가져와야 하므로 두 클래스 사이에 결합도가 생깁니다.
   - 따라서 공통으로 사용할 모델 객체는 같은 패키지 내 독립적인 파일이나 패키지 멤버 클래스로 분리해 주는 것이 훨씬 더 객체 지향적인 설계입니다.
