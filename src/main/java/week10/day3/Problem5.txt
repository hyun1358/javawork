[문제]
연습 문제 5 - 스레드 풀 안전한 종료
문제: 작업을 모두 마친 후 pool.shutdown()을 호출하고, 왜 종료해야 하는지 주석으로 남기세요.

[사용자 작성 코드]
package week10.day3;

public class Problem5 {
    public static void main(String[] args)
    {
        // TODO
        //shutdown을 안하면 쓰레드가 작업이 남아있다고 판단하고 게속 대기중 상태라 jvm종료가 안된다.
    }
}

[현재 코드 특징]
- 사용자는 스레드 풀을 정상 종료하지 않았을 때 백그라운드 스레드가 대기 상태를 유지하여 JVM이 종료되지 않는 원리를 정확하게 파악하고 주석으로 남겼습니다.
- 하지만 스레드 풀을 실제로 선언하고 작업을 제출한 후 종료하는 자바 코드 구현부가 누락되었습니다.

[Better Code]
package week10.day3;

import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class Problem5 {
    public static void main(String[] args) {
        // 1. 단일 스레드로 동작하는 스레드 풀을 생성합니다.
        ExecutorService pool = Executors.newSingleThreadExecutor();
        
        // 2. 간단한 출력 작업을 스레드 풀에 제출합니다.
        pool.execute(() -> System.out.println("작업 실행"));
        
        // 3. 더 이상 작업이 없음을 알리고 스레드 풀을 정상적으로 종료시킵니다.
        pool.shutdown();
        
        // [설명 주석]
        // shutdown을 안하면 쓰레드가 작업이 남아있다고 판단하고 게속 대기중 상태라 jvm종료가 안된다.
    }
}

[기술적 해설]
1. JVM 종료 조건:
   자바 가상 머신(JVM)은 프로그램 내부에 데몬 스레드(Daemon Thread)가 아닌 사용자 스레드(User Thread)가 단 하나라도 살아있으면 프로그램을 강제로 종료하지 않습니다.
2. 스레드 풀 스레드의 특성:
   스레드 풀이 생성하는 작업 스레드들은 대기 상태에 있더라도 사용자 스레드이기 때문에, `pool.shutdown()`을 통해 명시적으로 정지 명령을 내리지 않으면 JVM 프로세스가 영원히 백그라운드에 남게 됩니다.
3. 코드 구현의 보완:
   정확한 주석 개념을 바탕으로 실제 `ExecutorService` 객체의 생성, 작업 제출, 그리고 `shutdown()` 호출까지 자바 코드로 함께 구현하는 것이 필요합니다.
