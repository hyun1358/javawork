1. 채점 세부 내역
----------------------------------------------------------------------
[OK] enqueue(T item) (30점 만점 / 30점 획득)
     - list.add(item)을 통해 큐의 맨 뒷부분에 원소를 적절하게 이어 붙였습니다. 아주 깔끔합니다.

[▲] dequeue() (40점 만점 / 35점 획득)
     - 큐 자료구조의 선입선출(FIFO)에 가장 핵심이 되는 '0번 인덱스 삭제 반환(list.remove(0))' 메커니즘을
       단 한 줄로 완벽히 정밀 조준하여 작성하셨습니다!
     - 감점 요인(사소함): 리스트가 텅 비었을 때(list.isEmpty()) pop이나 dequeue를 하면 
       'IndexOutOfBoundsException' 에러가 터질 수 있습니다. 문제의 요구사항이었던 "(비어있으면 null 반환)"에 대한
       안전망(예외 처리) 한 스푼을 추가해 주면 100점 만점이 됩니다.

[OK] print() (30점 만점 / 30점 획득)
     - 향상된 for문을 활용해 데이터를 한 칸씩 띄워서 멋지게 한 행에 출력하고, 
       마무리 개행(System.out.println())까지 센스 넘치게 구현하셨습니다. 훌륭합니다!

----------------------------------------------------------------------
2. 코드 개선 제안 (더 견고한 소프트웨어를 위한 팁)
----------------------------------------------------------------------
실무 환경에서는 사용자가 큐가 비어있음에도 깜빡하고 데이터를 또 꺼내려고 할 때(dequeue)가 많습니다.
이때 프로그램이 뻗어버리는 참사를 방지하기 위해 아래와 같이 안전 장치를 다는 습관을 기르면 시니어 개발자 소리를 듣게 됩니다.

[수정 전]
public T dequeue() {
    return list.remove(0); // 빈 리스트인 경우 에러 발생
}

[수정 후 (안전장치 장착)]
public T dequeue() {
    if (list.isEmpty()) { // 혹은 list.size() == 0
        return null; // 비어 있다면 예외를 터뜨리지 않고 안전하게 null 반환
    }
    return list.remove(0);
}
