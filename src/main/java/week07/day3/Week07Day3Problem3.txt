[문제]: Checked vs Unchecked 예외의 가장 큰 차이점(컴파일 에러 발생 여부)을 설명하세요.

[사용자 작성 코드]:
//Checkd는 컴파일러가 강제로 예외를 처리할수있는 수단을 마련해놔야한다. IOExecption
//UnChecked는 프로그램머가 코드를 짜다가 실수난 부분이며 컴파일러가 강제로 예외처리를 안해도 실행은 되지만 오류발생 ArrayIndexException

[현재 코드 특징]:
- 두 예외의 핵심적인 차이인 '컴파일러의 강제성 여부'를 정확하게 짚어냈습니다.
- 각 예외의 예시(`IOException`, `ArrayIndexOutOfBoundsException`)도 적절하게 제시했습니다.

[Better Code]:
/*
 * 1. Checked Exception (예: IOException, SQLException)
 *    - Exception의 자식 클래스 중 RuntimeException을 상속받지 않은 클래스들입니다.
 *    - 컴파일 시점에 예외 처리를 강제합니다. (try-catch 혹은 throws 필수)
 *    - 주로 외부 자원(파일, DB, 네트워크)과의 상호작용 시 발생합니다.
 *
 * 2. Unchecked Exception (예: NullPointerException, ArrayIndexOutOfBoundsException)
 *    - RuntimeException의 자식 클래스들입니다.
 *    - 컴파일 시점에 예외 처리를 강제하지 않습니다.
 *    - 주로 개발자의 논리적 실수나 잘못된 데이터 사용으로 인해 발생하며, 코드를 수정하여 해결해야 하는 경우가 많습니다.
 */
public class BetterProblem3 {

[기술적 해설]:
1. 용어 정리: `Checked`는 '컴파일러가 체크한다'는 의미이고, `Unchecked`는 '체크하지 않는다'는 의미입니다.
2. 상속 구조: 모든 예외의 조상은 `Throwable`이지만, 실질적으로는 `RuntimeException`을 상속받았느냐 아니냐가 구분 기준이 됩니다.
3. 대응 방식: Checked는 예외가 발생할 가능성이 있는 상황에 대한 '대비(Handle)'가 목적이고, Unchecked는 코드의 '버그 수정(Fix)'이 주된 목적입니다.
