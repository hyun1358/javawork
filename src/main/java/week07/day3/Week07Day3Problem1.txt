[문제]: 입력값이 음수이면 throw new IllegalArgumentException을 던지는 메서드를 구현하세요.

[사용자 작성 코드]:
public class Problem1 {
    public static void main(String[] args)
    {
        // TODO

        try
        {
            Scanner sc = new Scanner(System.in);
            System.out.print("입력: ");
            int num = sc.nextInt();
            if(num < 0)
            {
                throw new IllegalArgumentException("음수여서 오류");
            }

        }
        catch (IllegalArgumentException e)
        {
            System.out.println("오류내용: "+e.getMessage());
        }
    }
}

[현재 코드 특징]:
- 사용자의 입력을 직접 받아 조건에 따라 예외를 명시적으로 던지는 `throw` 키워드를 잘 사용했습니다.
- 예외 발생 시 메시지를 함께 전달하여 `catch` 블록에서 원인을 파악하기 쉽게 구현했습니다.

[Better Code]:
package week07.day3;

import java.util.Scanner;

public class BetterProblem1 {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("나이를 입력하세요: ");
        
        try {
            int age = sc.nextInt();
            validateAge(age); // 검증 로직을 메서드로 분리
            System.out.println("입력된 나이: " + age);
        } catch (IllegalArgumentException e) {
            System.out.println("[입력 오류]: " + e.getMessage());
        } catch (Exception e) {
            System.out.println("알 수 없는 오류가 발생했습니다.");
        } finally {
            sc.close(); // 자원 해제
        }
    }

    /**
     * 입력을 검증하는 별도의 메서드입니다.
     * 이렇게 로직을 분리하면 다른 곳에서도 이 검증 로직을 재사용할 수 있습니다.
     */
    public static void validateAge(int age) {
        if (age < 0) {
            throw new IllegalArgumentException("나이는 음수일 수 없습니다: " + age);
        }
    }
}

[기술적 해설]:
1. 로직의 분리: `main` 메서드에서 입력을 받고 검증까지 직접 수행하는 것보다, `validateAge`와 같이 별도의 메서드로 검증 로직을 분리하는 것이 재사용성과 가독성 측면에서 훨씬 좋습니다.
2. 예외 메시지의 구체화: 예외를 던질 때 단순히 "음수 오류"라고 하기보다, 어떤 값이 들어와서 오류가 났는지(예: "나이는 음수일 수 없습니다: -5") 함께 적어주면 디버깅이 훨씬 편해집니다.
3. 자원 해제: `Scanner` 객체 사용 후 `close()`를 호출해주는 습관을 들이는 것이 좋습니다. (여기서는 `finally` 블록을 활용했습니다.)
