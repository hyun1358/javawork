[문제]
0으로 나누었을 때 발생하는 예외를 try-catch로 잡아 "에러 발생!"을 출력하세요.

[사용자 작성 코드]
public class Problem1 {
    public static void main(String[] args) {
        try
        {
            int a = 5 / 0;
        }
        catch(ArithmeticException e)
        {
            e.printStackTrace();
            System.out.println("오류 발생!");
        }
    }
}

[현재 코드 특징]
- ArithmeticException을 정확히 포착하여 프로그램 중단을 방지했습니다.
- e.printStackTrace()를 사용하여 디버깅 정보를 출력하는 좋은 습관을 보여줍니다.

[Better Code]
package week07.day1;

public class Problem1 {
    public static void main(String[] args) {
        try {
            int a = 5 / 0;
        } catch (ArithmeticException e) {
            // 문제 요구사항에 정확한 문자열 출력
            System.out.println("에러 발생!");
            // 실무에서는 getMessage()를 통해 예외의 구체적인 원인을 함께 출력하는 것이 좋습니다.
            System.out.println("원인: " + e.getMessage());
        }
    }
}

[기술적 해설]
1. 정확한 요구사항 반영: 코딩 테스트나 실무 협업에서는 지정된 출력 메시지("에러 발생!")를 정확히 지키는 것이 중요합니다. ("오류 발생!"과는 다릅니다.)
2. 예외 정보 활용: 단순히 에러가 났음을 알리는 것보다 e.getMessage()를 활용해 "/ by zero" 같은 시스템 메시지를 함께 보여주면 사용자가 상황을 더 쉽게 이해할 수 있습니다.
3. 로깅 위치: e.printStackTrace()는 콘솔에 아주 상세한 경로를 남기므로, 사용자용 메시지 출력 전후 어디에 배치할지 결정하는 감각이 필요합니다.
