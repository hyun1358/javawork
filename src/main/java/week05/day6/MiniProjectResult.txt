[문제]: 도서관 관리 시스템 v1 구현 (Book, Library 클래스 설계 및 대출/반납 로직 완성)

[사용자 작성 코드]:
// MiniProject.java (최종 수정본)
static class Library {
    private Book[] books;
    int totalBooks = 0;

    Library(int size) {
        books = new Book[size];
    }

    void addBook(Book b) {
        if (totalBooks < books.length) {
            books[totalBooks++] = b;
        }
    }

    void showBooks() {
        for (int i = 0; i < totalBooks; i++) {
            System.out.println(books[i].getTitle() + "(" + (books[i].isBorrowed() ? "대출중" : "대여가능") + ")");
        }
    }
    // ... borrowBook, returnBook 로직 포함
}

[현재 코드 특징]:
- 사용자님께서 직접 디버깅을 통해 NullPointerException과 static 오용 문제를 완벽히 해결하셨습니다.
- 객체의 상태(totalBooks)를 인스턴스 변수로 관리하여 객체지향의 기본 원칙을 잘 준수했습니다.
- 반복문의 범위를 유동적으로 제어하여 프로그램의 안정성을 확보했습니다.

[기술적 해설]:
1. **인스턴스 변수 vs 클래스 변수**: `static`을 제거함으로써 여러 개의 도서관(예: 강남 도서관, 종로 도서관)을 독립적으로 운영할 수 있는 구조가 되었습니다.
2. **배열 안전성**: `i < books.length` 대신 `i < totalBooks`를 사용한 것은 실무에서 매우 중요한 '방어적 프로그래밍' 기법입니다. 데이터가 없는 빈 공간을 참조하지 않도록 보장합니다.
3. **코드의 완결성**: 버그 수정 과정을 통해 자바의 메모리 구조와 실행 흐름(Switch-case)에 대한 이해도가 매우 높아졌음을 확인할 수 있습니다.
