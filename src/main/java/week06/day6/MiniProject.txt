[문제]: 상속과 다형성을 활용한 직원 관리 시스템 (급여 합계 계산 포함)

[사용자 작성 코드]:
public class MiniProject {
    public static void main(String[] args)
    {
        Employee[] employee = { new Manager("홍길동",1500000,100000),
                new Developer("개발자",2500000,500000),
                new Manager("관리자",3000000,500000),
                new Developer("고수개발자",5000000,1000000) };

        for(Employee e : employee)
        {
            System.out.printf("이름 : %s, 급여: %d\n",e.name,e.getSalary());
        }
    }
    // ... (중략)
}

[현재 코드 특징]:
- **상속과 다형성의 완벽한 이해**: `Employee`를 상속받아 `Manager`와 `Developer`를 정의하고, `Employee[]` 배열에 담아 처리하는 다형성의 핵심을 정확히 꿰뚫고 있습니다.
- **코드 재사용성**: `@Override`된 메서드 내에서 `super.getSalary()`를 호출하여 부모의 로직을 재사용하는 방식은 매우 수준 높은 코딩 습관입니다.
- **캡슐화 시도**: 필드를 `private`으로 선언하여 데이터 보호를 시도한 점이 훌륭합니다.

[Better Code]:
public class MiniProject {
    public static void main(String[] args) {
        Employee[] employees = { 
                new Manager("홍길동", 1500000, 100000),
                new Developer("개발자", 2500000, 500000),
                new Manager("관리자", 3000000, 500000),
                new Developer("고수개발자", 5000000, 1000000) 
        };

        int totalSalary = 0; // 합계를 저장할 변수

        for (Employee e : employees) {
            int salary = e.getSalary();
            System.out.printf("이름 : %s, 급여: %d\n", e.getName(), salary);
            totalSalary += salary; // 급여 누적
        }

        System.out.println("------------------------------------");
        System.out.println("전체 직원 급여 총합: " + totalSalary + "원");
    }
}

// 필드와 메서드 구조 개선 (Getter 활용 및 오타 수정)
class Employee {
    private String name;
    private int baseSalary;

    public Employee(String name, int baseSalary) {
        this.name = name;
        this.baseSalary = baseSalary;
    }

    public String getName() { return name; }
    public int getSalary() { return baseSalary; }
}

[기술적 해설]:
1. **요구사항 완결성**: 프로그램의 목적은 '관리'와 '합계 계산'입니다. 개별 데이터 출력 후 이를 종합하는 `totalSalary` 로직을 추가하여 프로그램의 완성도를 높였습니다.
2. **오타 교정**: `basaeSalary`와 같은 사소한 오타는 컴파일에는 지장이 없으나, 협업 시 가독성을 해칠 수 있습니다. IDE의 자동 완성 기능을 활용하여 정확한 명칭을 사용하는 습관이 중요합니다.
3. **확장성**: `Employee` 클래스에 `getName()` 같은 Getter를 추가하면, 나중에 외부 패키지에서도 안전하게 정보에 접근할 수 있습니다.
