[문제]: 다형성과 인터페이스
인터페이스 타입 배열을 선언하고 그 안에 구현 객체들을 넣어 일괄 처리해보세요.

[사용자 작성 코드]:
package week06.day5;

public class Problem5 {
    public static void main(String[] args)
    {
        Flyable[] flyable = {new Duck(), new Airplan() };
        for(Flyable f : flyable)
            f.fly();
    }

    interface Flyable
    {
        void fly();
    }

    static class Duck implements Flyable
    {
        @Override
        public void fly()
        {
            System.out.println("오리가 하늘을 날다.");
        }
    }

    static class Airplan implements Flyable
    {
        @Override
        public void fly()
        {
            System.out.println("비행기가 하늘을 날다");
        }
    }
}

[현재 코드 특징]:
- 인터페이스를 활용한 다형성의 핵심인 '일괄 처리'를 배열과 루프로 깔끔하게 구현했습니다.

[Better Code]:
package week06.day5;

public class Problem5 {
    public static void main(String[] args) {
        Flyable[] flyers = { new Duck(), new Airplane() };

        System.out.println("[비행 관제 시스템 가동]");
        for (Flyable flyer : flyers) {
            flyer.fly();
        }
    }

    interface Flyable {
        void fly();
    }

    static class Duck implements Flyable {
        @Override
        public void fly() {
            System.out.println("오리가 수면 위에서 날개를 치며 비상합니다.");
        }
    }

    static class Airplane implements Flyable {
        @Override
        public void fly() {
            System.out.println("비행기가 엔진 소리와 함께 구름 위로 날아오릅니다.");
        }
    }
}

[기술적 해설]:
- 클래스 이름 `Airplan`은 오타로 보이며, `Airplane`이 정확합니다.
- 변수명 `flyable` 보다는 복수형인 `flyers` 혹은 `flyableItems`와 같이 명확한 이름을 사용하는 것이 가독성에 좋습니다.
- 로직상 오류는 없으며, 인터페이스를 통한 타입 통합 능력이 돋보입니다.
